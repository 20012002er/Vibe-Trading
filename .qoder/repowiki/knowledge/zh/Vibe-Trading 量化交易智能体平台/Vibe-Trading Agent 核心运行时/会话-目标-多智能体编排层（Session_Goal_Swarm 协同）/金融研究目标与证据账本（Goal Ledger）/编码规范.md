- 所有写操作通过 `_synchronized` 装饰器在 `RLock` 内串行，并使用 `_write_transaction` 上下文管理器包裹 `BEGIN IMMEDIATE` 事务以保证原子性。
- 可变写入方法统一要求 `session_id`、`goal_id`、`expected_goal_id` 三参数，并由 `_require_mutable_goal` 校验目标仍在当前会话且处于 `_CURRENT_STATUSES` 集合中的活跃状态。
- 用户输入先经 `normalize_required_text` 去空白校验，再经 `reject_live_execution_objective` 的正则匹配拒绝任何带下单/交易语义的目标或准则。
- JSON 字段（如 `symbol_universe`、`benchmark`、`assumptions`、`contradicts_claim_ids`）统一通过 `_json_dumps`/`_json_loads` 序列化为 TEXT 列存储。
- 所有 ID 由 `_id(prefix)` 生成，以语义前缀（`goal_`、`crit_`、`ev_`、`claim_`、`audit_`）加 hex 片段区分类型。
- 从 SQLite Row 反序列化为 dataclass 的方法（`_goal_from_row`、`_criterion_from_row`、`_claim_from_row`、`_evidence_from_row`）集中放在类末尾，保持 ORM 映射逻辑收敛。
